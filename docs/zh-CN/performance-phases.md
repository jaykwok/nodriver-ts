# AX 与队列测量

[English](../performance-phases.md) · [基准方法](performance.md)

`npm run bench:mcp`，Windows x64 / Ryzen 5 5600X / Chrome 155 / Node.js 24.22.0，headless。预热后每组 7 次 AX、5 轮并发；fixture 新增带深层按钮的命名 section。

| 传输      | 按钮数 |  AX 字节 | 输出字节 | 总耗时 p50 / p95 ms | 发送→接收 p50 ms | 分派 p50 ms | 分派后 p50 ms |
| --------- | -----: | -------: | -------: | ------------------: | ---------------: | ----------: | ------------: |
| Pipe      |    100 |   142283 |     8881 |         6.75 / 7.85 |             4.89 |        0.67 |          0.48 |
| Pipe      |   1000 |  1355663 |    16089 |       63.47 / 67.31 |            48.11 |        5.91 |          1.93 |
| Pipe      |  10000 | 13612812 |    16093 |     644.27 / 701.30 |           480.11 |       61.84 |         15.21 |
| WebSocket |    100 |   142290 |     8881 |         7.69 / 8.35 |             5.77 |        0.67 |          0.36 |
| WebSocket |   1000 |  1355667 |    16089 |       81.56 / 87.92 |            65.15 |        5.98 |          1.56 |
| WebSocket |  10000 | 13612816 |    16093 |     750.26 / 848.28 |           554.86 |       92.10 |         17.67 |

以上是控制器观测。发送→接收包含 Chrome 计算/序列化、传输、OS 调度及字符串回调前解码。分派包含 Connection JSON 解析、验证和响应交付；分派后包含过滤/ref 转换、微任务和密码保护等额外 DOM 请求，不是纯转换 CPU 时间。观测器额外解析 JSON、计算字节；10000 按钮时其中位成本为 Pipe 64.44 ms / WebSocket 86.64 ms，计入总耗时但独立于分派。字节不含分帧，各阶段中位数不一定相加为总耗时中位数。Chrome 内部计算与传输/序列化无法在此分开。

10000 按钮 Pipe fixture 上的替代请求：

| 请求              |     ms |       字节 | 是否完整             |
| ----------------- | -----: | ---------: | -------------------- |
| 完整 AX 树        | 645.82 | 13,612,812 | 是                   |
| depth=1           | 356.03 |  7,137,890 | 否，漏掉深层按钮     |
| depth=2           | 523.07 | 11,011,057 | 否，漏掉深层按钮     |
| partial（6 节点） |   3.29 |     75,200 | 否                   |
| 无过滤 root query |   7.22 |      3,619 | 仅在这个简单页面完整 |

带 root 的 `browser_snapshot` 仍读取完整树，再只返回 root 下的语义节点。

`npm run bench:ax-subtree` 在四种 frame 和 closed shadow host 上尝试 root query：主 frame、同进程 root 与完整树结果一致，但跨进程和嵌套 frame 的查询在两种传输中都无法及时返回，因此 root query 不能普遍替代完整读取。快照保留完整读取及 root/frame 校验、ref 生命周期和分页，不把部分结果当作完整快照。按需展开需要 `Accessibility.enable`。

| Reads |         20 |      5 |     18.63 / 29.86 |  749.19 |            9.51 / 22.89 |
| Mixed |          1 |      1 |   308.99 / 310.02 |    3.23 |           0.001 / 0.002 |
| Mixed |          5 |      2 | 1249.57 / 1264.41 |    3.98 |          10.85 / 930.76 |
| Mixed |         20 |      5 | 1265.59 / 1289.18 |   15.68 |          23.83 / 936.76 |

Reads 为每 Context 一次快照，Mixed 为 fill→click→snapshot 并核验文本；不同浏览器进程可并行。浏览器队列记录逐操作等待，任务延迟包含整个负载与 MCP 分派，Session 队列 p50 小于 0.01 ms。混合负载较高的排队尾部来自焦点与输入的串行化，这是有意为之：同一租约内的操作（包括快照与 ref 解析）保持串行，`readOnlyHint` 不改变调度。

基准以 JSON 输出全部样本；比较改动前请在目标平台上运行。AX 内存表现见[长稳测试](soak.md)。
