# API and behaviour

[简体中文](zh-CN/api.md)

Every operation is asynchronous except read-only properties and event subscriptions. Public types are exported from the root entry point `nodriver-ts`, and the build ships `.d.ts` files. CDP types come from `devtools-protocol`, which is installed with the package.

Raw CDP applications can use `attach: 'none'` and `browser.attachSession(targetId, options)`. `TargetSession` extends `Session` with `targetId`, `ended`, `endReason`, and `detach()`. See [the raw-session contract](raw-sessions.md) for lifecycle, cancellation, `observe.onSend` / `onSettle` / `onResponse`, and `connection.unansweredCount`.

## Deadlines and cancellation

`WaitOptions` combines a `timeout` in milliseconds with an `AbortSignal`. A timeout outside 0–2147483647 ms throws `RangeError`; 0 expires immediately and does not mean "wait forever".

| Operation                                            | Default deadline                                                                |
| ---------------------------------------------------- | ------------------------------------------------------------------------------- |
| Launching or connecting to Chrome, CDP handshake     | 30 s                                                                            |
| A single protocol command                            | 30 s; `launch({ timeout })` sets both the launch/handshake and command deadline |
| `waitForSelector`, `waitForFunction`, action polling | 10 s, polling every 50 ms                                                       |
| `inspectEnvironment`                                 | 5 s                                                                             |
| `diagnoseEnvironment`, `alignEnvironment`            | 10 s                                                                            |

`sendWith(method, { timeout, signal }, ...params)` sets a deadline and cancellation for one command. Multi-step operations share one budget: each step of a selector query (the execution-context wait and every DOM/Runtime request) gets only the remaining time, and so does each attempt of `waitForSelector()` / `waitForFunction()`. Concurrent callers share one execution-context lookup; a caller that times out or is cancelled ends only its own wait. Releasing a query's object group has its own 1 s deadline and does not delay the caller's return.

A host-side deadline or cancellation only stops waiting. CDP commands already sent, page scripts already run and input already dispatched are neither undone nor replayed.

## Navigation and event waits

Navigation waits for `load` by default; `domcontentloaded`, `commit` and `networkidle` (Chrome's networkIdle lifecycle event) are also supported. SPA/hash navigations complete on the same-document navigation event, and BFCache restores complete on the restore event. Once a new document has committed, a same-document change such as `history.replaceState()` only updates the URL the wait resolves with; the wait still ends at the requested lifecycle event. `reload()` completes only with a new document, and `go()` completes a same-document history navigation only when the page reaches the entry's URL.

Register waits for navigation, downloads, popups and responses before triggering the action. A closed session rejects its pending requests and event waits, and late responses are dropped. `tab.crashed` reports a crash of the page's own renderer; a crash of an out-of-process iframe does not set it. `reload()` or `goto()` recovers a crashed page: a new main-frame document clears the flag, and old handles stay invalid. After a disconnect, open a new connection; the library does not replay scripts or input.

## Queries

- A selector is a CSS string, `{ css }`, `{ xpath }` or `{ text, exact? }`.
- CSS and text queries pierce open and closed shadow roots by default; `pierce: false` turns this off. XPath follows standard semantics and does not cross shadow roots.
- Text matching collapses whitespace and, by default, returns only the smallest visible elements that do not contain a matching child.
- `Frame.query()` searches only the selected frame and never crosses into iframes. `Element.query()` is scoped to the element's subtree.
- A query walks the document and open shadow roots in a single pass inside a randomly named isolated world. When piercing (the default), closed shadow roots are found with `DOM.getDocument`. If none are found, that result is reused for the same document for up to 1 s while the structure is unchanged; if some are found, they are cached until the DOM structure changes and passed to the same single pass.
- `QueryOptions` accepts `pierce`, `visible`, `limit` (10,000 matches by default), `timeout` and `signal`. Polling is not meant for high-frequency full scans of large pages.

## Evaluation and execution worlds

`evaluate()` runs in the main world by default; `{ world: 'isolated' }` uses an isolated world. DOM helpers always use a randomly named isolated world. Isolated worlds share the DOM with the page, so the page can observe DOM changes and input events.

Functions run in the browser and cannot capture host closures. Arguments are passed as one serializable value, and a `JSHandle` can be an argument. Exceptions in user scripts throw `EvaluationError`. The string form of `evaluate` / `evaluateHandle` accepts a positive `executionTimeout` in milliseconds. It maps to `Runtime.evaluate.timeout`: it limits only the initial synchronous run, cannot stop timers, requests or async continuations that were already scheduled, and is not a resource sandbox. `Element.withObject(fn)` runs `fn(objectId, group)` with a handle to the element in the isolated world; objects that `fn` creates in `group` are released together with the handle.

The library does not call `Runtime.enable`. The main world is resolved and validated through the owning frame's Document and `DOM.resolveNode`; see the [automation audit](automation-audit.md). Runtime events are therefore not delivered; sending `Runtime.enable` yourself through `cdp` delivers them but changes the detection surface. Register `addInitScript()` before `goto()`. A new OOPIF is initialized while paused and then resumed, with a watchdog as a fallback. Popups and external pages that have already started running get no guarantee that the script runs before their first script.

## Launch and connect

| Option                            | Behaviour                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `headless`                        | `false` by default. Must be set to `true` explicitly without a graphical desktop; the library never switches automatically when no display is available                                                                                                                                                                                                                                                                                                                   |
| `maskHeadless`                    | Off by default; explicit true removes HeadlessChrome from page UA/UA-CH when no `userAgent` is given; Shared/Service Worker values can differ                                                                                                                                                                                                                                                                                                                             |
| `automationControlled`            | `false` by default: adds `--disable-blink-features=AutomationControlled` (merged with the caller's other disabled features) and keeps the native webdriver getter; `true` omits the switch                                                                                                                                                                                                                                                                                |
| `preset: 'agent'`                 | Appends `AGENT_ARGS` (unless `args` already sets the same switch): disables the search engine choice screen, the crash-restore bubble and background throttling, and sets `--password-store=basic`. On Linux, Chrome then encrypts saved passwords and cookies with its built-in key instead of the system keyring and never prompts for it; a persistent profile whose data was encrypted through the keyring cannot read that data. First-run UI is off in every launch |
| `userAgent`, `lang`, `windowSize` | Set the UA, BCP 47 language and window size at launch                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `userDataDir`                     | Persistent profile, locked by `acquireProfileLock()` (see below)                                                                                                                                                                                                                                                                                                                                                                                                          |
| `handleSignals`                   | Host signals are not handled by default. With `true`, SIGINT and SIGTERM close every browser launched with this option; the signal is then re-raised so the host terminates as it would by default, unless the host has its own handler for it                                                                                                                                                                                                                            |
| `detached`                        | `false` by default; `true` allows a detached launch on Windows/Unix and `release()`. WebSocket only; Chrome stderr is discarded unless `supervised` is set                                                                                                                                                                                                                                                                                                                |
| `supervised`                      | With `detached: true`: a helper process ends Chrome if the host dies before `release()`, and keeps a bounded tail of its stderr; see [supervised launch](lifecycle-ownership-design.md)                                                                                                                                                                                                                                                                                   |
| `trace`                           | As for `connect`: a boolean or a callback; see [Protocol and tracing](#protocol-and-tracing)                                                                                                                                                                                                                                                                                                                                                                              |

The lock file of a persistent profile records the PID and host name. A stale lock is reclaimed only once the owning process on this host is confirmed to have exited, and reclamation is serialized by a separate `.nodriver.lock.reclaim` file. If a process is killed during reclamation and leaves that file behind, launch fails with a clear error; delete the file manually after confirming the recorded process has exited. A leftover `DevToolsActivePort` in the profile (left when Chrome did not exit cleanly, for example because an MCP host force-killed the server) is probed: if the recorded browser still answers on its port, launch is refused; otherwise the file is deleted and launch continues. When launch fails and Chrome has exited, the error includes the exit code and stderr.

`Browser.connect({ endpoint, attach })` connects to an existing browser. `'all'` (the default) attaches to every tab; `'created'` attaches only to tabs that this client creates and their popups. Launch options have no effect on a connected browser, and `close()` only disconnects, which also ends the contexts this connection created with `proxy` (see [Environment](environment.md#proxies-and-webrtc)).

`ProfileInUseError`, carrying the `profile` path, is thrown when the process holding `.nodriver.lock` on this host is still alive, when another process wins the race to reclaim a stale lock, or when `DevToolsActivePort` is still served by the original browser. On Windows the library also probes Chrome's native `lockfile` for a sharing violation (`EBUSY`), so a running Chrome without a debugging port also produces this error; a leftover file that is not locked does not count as in use, and neither do permission errors. On Unix the native `SingletonLock`/`SingletonSocket` are not inspected, so without a debugging port you may get an ordinary launch-exit error instead.

`await using` closes resources on normal exit and during exception unwinding; `try/finally` with `close()` also works. `close()` is idempotent, and a `close()` that failed can be called again. Chrome launched without `detached` also ends when the host exits, including through `process.exit()` or an uncaught exception. JavaScript cannot guarantee cleanup if the host is force-killed or loses power; see [browser handoff and events](browser-handoff.md) for what remains in that case.

`await browser.release()` returns the WebSocket endpoint and gives up ownership of the process. Afterwards `owned` is `false`, and `close()` and async disposal only disconnect. An owned browser must have been launched with `detached: true`; a pipe connection rejects handoff explicitly and is left unchanged. Handoff keeps the profile (a temporary one too) and `DevToolsActivePort`, and removes the `.nodriver.lock` that records the host PID. `disconnect()` does not give up ownership, and a pipe Chrome exits when its pipe closes. Without `supervised`, a host crash before handoff can leave Chrome running. See [browser handoff and events](browser-handoff.md) for a full example, cleanup responsibilities and the event API.

## Input and element actions

- Before a click, the element is scrolled into the viewport and checked for visibility, enabled state, stable position and hit-testing. A control inside a disabled `<fieldset>` counts as disabled, and a hit on the element's shadow tree or on a frame it contains counts as a hit on the element. Actions already dispatched are never replayed.
- `fill()` supports editable inputs, textareas and contenteditable elements. It writes Unicode through focus/selection and `Input.insertText`, and promises only the final text and the browser's input semantics; it does not simulate an OS IME candidate window or the clipboard.
- `select()` changes the value through the DOM and dispatches input/change.
- Physical keys support named keys, F1–F12, modifier combinations and US-layout characters (including shifted symbols).
- `Mouse.drag()` is a pointer drag; complex HTML5 DataTransfer needs your own protocol code.
- Cancellation and deadlines reject with `InputActionError`, whose `cleanup` reports how held keys and buttons were released. Element input stops when the element's frame or any ancestor frame navigates or detaches; raw Tab mouse/keyboard input watches the main frame.
- `browser.inputScope(session)` and `createInputScope(session)` group mouse, keyboard and composition calls under one deadline and report. See [Input](input.md).

## Screenshots, PDF and errors

`screenshot()` returns a Buffer; `path` is optional. Element screenshots suit axis-aligned elements; for rotated or perspective-transformed elements, take a page screenshot with an explicit clip. `pdf()` relies on Chrome's headless printing. Permission problems, experimental commands and differences between browser implementations surface as `ProtocolError`; they are not all treated as "unsupported".

## Network

`Network.enable` is sent only when needed: subscribing to `responses`, calling `waitForResponse`, calling `enable()` explicitly, or setting non-default headers/cache/offline. Each subscription or `enable()` call retries a setup that failed; one that succeeded is not repeated. `route()` and `authenticate()` use only the Fetch domain; if Chrome refuses the change on any session, they reject and restore the previous routes or credentials. `setExtraHeaders()` rejects invalid header names and values with `TypeError` before sending anything. Headers, cache and offline settings are kept, and applied to later sessions, only once Chrome accepts them. Sessions that close during these calls are skipped.

A route handler that throws before answering is reported through `onError` and `browser.errors`, and its request is aborted. An answer Chrome refuses rejects with `ProtocolError` and leaves the route open: the handler can answer again, and a request it leaves unanswered is continued. An answer to a request Chrome no longer holds, because the page cancelled it or the route was removed, resolves without effect. Routes cover the selected Tab and its OOPIFs, but not Service Workers, the browser's own requests or other tabs. Call a response's `body()` after its content is available; CDP may refuse when the cache entry was evicted or the response was redirected.

## State and storage

Cookies and storage are isolated between BrowserContexts. That isolation does not extend to the operating system, GPU or fonts.

`storageState(path?)` saves cookies, plus first-party localStorage for every HTTP(S) origin that any frame in the context has visited, including iframes and origins used by tabs that have since closed. Empty storage is not exported. Partitioned localStorage of cross-site iframes under other top-level sites, sessionStorage and IndexedDB are not in the snapshot. Main pages that are still open are read in place; other origins are read in one temporary tab.

`restoreStorage(state)` sets cookies first, then replaces the localStorage of each listed origin. If a main page for that origin is still open, it is written in place and readable once the call returns; other origins are written in one temporary tab. The temporary tab intercepts document requests, serves a blank page and bypasses Service Workers, so it never contacts the site, follows redirects or runs site scripts. Other open documents of the same origin receive the change asynchronously, just as with cross-tab writes in the browser.

`Frame.storage(kind = 'local', origin?)` and `Frame.setStorage(values, kind = 'local', clear = false, origin?)` accept an expected origin. Reading, clearing and writing happen in the same script as the `location.origin` check; on a mismatch they throw `EvaluationError` and the page's storage is left unchanged.

Cookie snapshots and state files contain credentials. Where they are stored is the caller's responsibility.

## Protocol and tracing

Strict command parameter tuples, return types and event types come from a pinned version of `devtools-protocol`. Events are routed by session: `session.on(method, listener)` and `session.onAny(listener)` receive only that session's events, and run before the global `connection.events`. `connection.listenerCount` counts both.

The `trace` option of `launch()`, `connect()` and `Connection` accepts `true`, which writes each command's method, session, duration and error code or name to stderr, or a function, which receives a `TraceEntry` instead. Without the option, `NODRIVER_TRACE=1` (or `true`) enables tracing; `trace: false` disables it regardless. Parameters and results are never logged.
