# Local differential browser audit

[简体中文](zh-CN/differential-audit.md)

`npm run bench:audit` emits JSON to stdout and progress to stderr. Node.js 24+ and a local Chrome are required. Run on an idle machine when interpreting timing; ordinary CI checks functionality and preserves observations, without timing thresholds or detector scores. `AUDIT_REPEATS` defaults to 2; `AUDIT_TRANSPORTS=websocket,pipe` and `AUDIT_VARIANTS` select the library matrix. `AUDIT_HEADFUL=1` is an explicit opt-in for an idle graphical desktop: the audit creates its own windows and tabs, which can affect focus. It never attaches to personal browsing profiles.

## Attribution and controls

Every run starts with its own empty disposable profile, no extensions, no inherited permissions/cache/Worker registrations, the same viewport request and the same local probes. Profiles are not copied or shared between runs. The only intentional within-run reuse is the Service Worker registration across a controlled reload. Browser process arguments, executable, actual library browser version, OS/runtime, transport, repeat, operation sequence, environment overrides and all CDP requests are recorded. Raw groups use the same executable and record the page's UA/high-entropy version; they do not query CDP for a version.

| Group         | Configuration and collector                                                                                                                                                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A-native      | Chrome launched without a debugging flag or library automation-feature flag. Page self-reports; no CDP client exists. With the default audit settings this is native **headless**, not a physical human/headful baseline. |
| A-matched     | A plus `--disable-blink-features=AutomationControlled`, isolating that launch flag from the debugging endpoint.                                                                                                           |
| B-endpoint    | Matched flags plus a loopback debugging endpoint; no client connects.                                                                                                                                                     |
| C-raw         | Same as B, then a browser WebSocket opens without sending any CDP command. Both C and its B control receive the same sampling delay.                                                                                      |
| D-attached    | Sample an already loaded page, initialize `Browser.connect`, sample that same document, disconnect, and sample again. No navigation or input occurs between these three observations.                                     |
| D-initialized | Full `Browser.launch`, not merely a connection. Initialization is recorded before opening the test page; explicit masking includes its temporary `chrome://version` probe and overrides.                                  |
| E-operations  | Separate DOM read, full AX read, fill/click, wheel, background-tab and navigation phases, with page-owned sampling after each operation.                                                                                  |

Raw groups are WebSocket controls. Pipe has no equivalent of an unconnected TCP endpoint, and is not presented as an identical B/C control. D creates an initial blank tab and then the fixture tab, closes the initial tab and measures with one fixture tab; raw Chrome starts directly at that URL. This different startup history remains a limitation. Focus/visibility, screen/viewport and window geometry are reported; OS occlusion, GPU/OS scheduling and physical input are not controlled by the automated matrix. Backgrounding one of the audit's own tabs is distinct from OS occlusion and from headless mode.

## Shared probes and interpretation

The exact page script runs in every group. It collects navigator fields, low/high-entropy Client Hints, navigator/window/chrome descriptors, global names, a bounded mutation/event log, explicit form/click/scroll results, visibility/focus/lifecycle events and distributions of interval/rAF samples. Expected DOM changes are separate from extra mutations and descriptor/global differences. Sampling windows reset after each phase; `background-start` separates tab-switch transition from the following background window. Small samples, absent rAF callbacks and scheduler noise are observations, not detection verdicts.

The same script creates Dedicated and Shared Workers, registers/activates/claims a scoped Service Worker, reloads with that existing registration, then unregisters it and closes worker resources. Each context reports its native navigator and makes a request to the same loopback receiver. Worker creation, registration, local requests, MutationObserver, timers, rAF and JSON serialization all have costs; every group bears those costs. No native getters are patched and no code is injected into unrelated Workers. Service Worker code does not intercept requests.

Workers are sampled again after **every** operation, using response IDs to exclude late responses from a previous phase. HTTP records and navigator comparisons are matched by run, context, phase and document lifecycle. They are not reused from the initial sample. The attached group provides a same-document WebSocket initialization control; the separate launched D/E matrix still retains the startup-history and Pipe-control limitations above.

Values distinguish `observed`, `unsupported`, `unavailable` and `not-observed`. Worker-only missing APIs are not required to equal Window APIs. The loopback origin is a secure context; JavaScript Client Hints availability and high-entropy promises are recorded separately from HTTP hints, which depend on request type and Accept-CH negotiation. A missing request hint is `not-observed`, not a claim that the corresponding JS field is unsupported. Requests and request-vs-navigator summaries preserve these differences.

Domain records include session IDs and actual enable/disable commands, plus `DOM.getDocument` because it starts DOM structure events. In the measured default operations only Page.enable and DOM.getDocument appeared; CSS/Network/Accessibility.enable were not required by these operations. Other APIs may enable them on demand. Closing owned sessions/processes cleans up this run; the tool never blindly disables a domain used by another caller. Modern discovery and Main World objectId validation are covered separately by the audit/compat suites.

Font diagnostics now enable DOM/CSS only on temporary independent target sessions and detach those sessions afterward. A four-frame regression verifies actual font output and that a caller-owned CSS subscription still receives stylesheet events. The audit includes a separate explicit fonts phase; these commands are reported separately from the basic-operation domain observations above.

## Regression gate

JSON schema version 2 includes `validation.passed`, the number of checks, failures with run/phase/criterion, and explicitly allowed exceptions. The command exits nonzero when required raw/attached controls or operation samples are missing, a Worker fails to report, native fields diverge, descriptors/globals change, an unexpected DOM mutation occurs, a context's HTTP UA differs from its own navigator, Service Worker control is lost, or scoped cleanup fails. Own navigator properties are checked as well as prototype descriptors.

Opt-in UA/locale/timezone differences are bounded: Worker values must match either their native control or the explicitly overridden document. This exception cannot excuse an unrelated field change or an arbitrary new value. Timing, display geometry, focus and visibility remain observations, not equality gates. `test/unit/audit-checks.test.ts` corrupts valid evidence to verify these failures, including missing samples, injections, wrong headers and failed cleanup. A passing report is a regression result for these probes, not proof of undetectability.

## Measured results and decisions

Windows x64 / Chrome 155.0.8059.85 / Node.js 24.22.0, 2026-10-21: two repeats, both library transports, six variants plus four raw groups produced 32 runs, 248 page reports and 536 local request records. All Worker types were observed. Initial Service Worker registrations were new; controlled reloads found their own existing active registration and controlled page. All cleanup unregisters succeeded. No forbidden automatic CDP commands were sent. Relative to matched controls, navigator/window/chrome descriptors and global-name sets showed no differences under these probes. This limited result does not prove absence of other signals.

| Variant                                                 | Observed environment differences                                                                                                                                                                                      |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native UA, including default/agent/single-flag controls | No document-versus-worker differences among comparable supported fields.                                                                                                                                              |
| `maskHeadless: true`                                    | Page and Dedicated Worker UA (and their requests) used Chrome; Shared/Service Worker UA and requests retained HeadlessChrome. Reproduced on new and controlled pages, both repeats/transports.                        |
| Explicit UA + locale + UTC                              | Dedicated Worker inherited UA but retained native language values; Shared/Service Worker retained native UA/language/Client Hints. HTTP observations agreed with each context's own UA, not with every other context. |

The optional mask hides one headless identifier but introduces a direct cross-context contradiction. **`maskHeadless` now defaults to false**; explicit true retains the previous behavior for callers who need it. No Worker patches were added. This favors native consistency over a partial override and can change what sites observe; no claim of lower detection rates follows.

Default, agent and each individual background-related flag all reported hidden/blurred when another audit tab was foregrounded. Their short headless timer/rAF samples do not establish an OS occlusion effect or a reason to remove reliability flags. The `agent` preset remains explicit and unchanged. Headful/native, physical input and other platform/version matrices remain unverified in this run. For AX cost and memory evidence see [performance phases](performance-phases.md) and [soak](soak.md); costs alone do not demonstrate a stable page-visible signal.

A subsequent isolated Pipe run on the same host used two repeats and reset the window after the tab-switch transition: 16 launches, 120 reports, 264 requests, including the new explicit font phase and the actual omitted-mask default. In roughly 2 s background windows, every configuration was hidden/unfocused and had zero rAF callbacks. Interval medians (two repeats, ms) were default 1003.0 / 993.5, agent 991.6 / 1002.4, occluded flag 990.7 / 988.3, renderer flag 1003.8 / 991.2; p95 was 1000.5–1004.0 ms across these windows. This small experiment describes tab-background throttling, not physical occlusion or a guaranteed timer policy. The new native default showed no comparable Worker differences, and the font phase enabled DOM/CSS only on its temporary sessions. A prior run overlapping functional tests was used only for functionality, not these timing conclusions.

The regression-gated rerun on the same Windows/Chrome/Node versions passed **17 headless runs / 153 samples / 612 request records / 13,878 checks** (one repeat, both transports, all six variants) and **11 headful runs / 87 samples / 348 request records / 7,768 checks** (one repeat, Pipe library matrix, all six variants). Both include the WebSocket attached control. That control showed no measured environment-field, descriptor or global-name change during initialization; checks after disconnect also passed. Headless recorded 240 and headful 100 field-level opt-in exceptions, not failures. The runs were separate; these functional results do not establish timing equivalence, physical input or OS-occlusion behavior. Reports are generated locally as `test-results/audit-gated-headless.json` and `test-results/audit-gated-headful.json` (ignored artifacts).

## Physical/manual collection

Run `npm run bench:audit:manual` and keep the collector terminal open. It creates only a local service, prints a URL and never creates a browser, CDP connection or input. Launch Chrome yourself with a newly created empty disposable `--user-data-dir` and that URL, with **no debugging flags**, no extensions or personal profile. Record the full command, Chrome/OS version, display, window arrangement and focus alongside the JSON.

Use a physical keyboard/mouse to fill/click/scroll; use the page's Record button for repeated samples, reload once for the existing Service Worker stage, then compare foreground, background and genuinely covered windows manually. Keep those conditions separate. Check the attestation only if physical devices were used, then click Finish. The collector unregisters its own Worker and writes `test-results/audit-manual.json`; close this Chrome and remove only its disposable profile. Attestation is not independently verified. CDP-generated trusted events and script events do not count as a physical baseline. No physical sample was collected during this implementation.

The Linux push CI runs a reduced native/masked/explicit-environment audit with these regression assertions and JSON artifacts. The independent Beta/Dev/Canary workflow runs the same gate alongside strict objectId and lifecycle suites, on a weekly schedule, manually, and for PRs changing its workflow or relevant core/audit files. Preview failures stay visible and do not become a stable release requirement. CI does not replace an idle-machine benchmark or physical/manual collection.
