# Browser behavior

[简体中文](zh-CN/automation-audit.md)

The library discovers execution contexts without `Runtime.enable` and runs DOM helpers in an isolated world. This page describes its default CDP usage, input events and browser settings, along with measurements from specific browser configurations.

## Default behaviour

| Area                   | Behaviour                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Runtime.enable         | Never sent automatically for main pages, popups, same-process iframes, nested OOPIFs or reconnects, and never enabled then disabled. The Console and Debugger domains are not enabled either                                                                                                                                                                                                                                                                                                                                                                                               |
| Finding the main world | `Page.createIsolatedWorld` targets the exact frame; isolated-world Document → `DOM.describeNode` → `DOM.resolveNode` (without executionContextId) yields the main-world object for the same Document                                                                                                                                                                                                                                                                                                                                                                                       |
| objectId validation    | Strict checks of the V8 format, context scope, the isolated world's official ID, isolate identity and the main-world Document's backendNodeId. An incompatible format throws `UnsupportedError`; there is no fallback to enabling Runtime                                                                                                                                                                                                                                                                                                                                                  |
| Context lifecycle      | The cache is bound to the frame, session and document generation, and is invalidated by navigation, BFCache, process swaps, crashes and `setContent`. A vanished context is rediscovered on the next call; the current user script is not replayed                                                                                                                                                                                                                                                                                                                                         |
| Temporary objects      | Objects created during discovery are released by objectGroup in `finally`, and cleanup is still attempted after the caller cancels                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Main-world injection   | No `Runtime.addBinding`, postMessage channel, inserted script or library global, and no fixed sourceURL. Explicit user evaluate/addInitScript calls keep their own semantics; isolated-world init scripts use a random world name per tab                                                                                                                                                                                                                                                                                                                                                  |
| DOM helpers            | Queries and action checks run in a randomly named isolated world without requesting universal cross-origin access                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| navigator.webdriver    | Turned off with Chromium's AutomationControlled launch switch. The getter stays native, and no property is added to navigator                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Headless UA            | `maskHeadless` (opt-in, ignored when `userAgent` is set) uses `Emulation.setUserAgentOverride` on page sessions to remove HeadlessChrome, and attaches the native UA-CH read from `chrome://version` so Client Hints do not disappear. Documents, HTTP request headers and dedicated workers agree; shared and service workers are separate targets and may keep the original value                                                                                                                                                                                                        |
| Protocol surface       | `Network.enable` is sent on demand; routing and authentication use only the Fetch domain. Piercing queries (the default) use `DOM.getDocument` to find closed shadow roots, which makes that session receive DOM structure events                                                                                                                                                                                                                                                                                                                                                          |
| Input                  | With key-event typing (the human-mode default), US-layout characters are sent as rawKeyDown, char and keyUp, with Shift added for capitals and shifted symbols; modifiers and keys without text send no char. Left, right and numpad keys report their location. Pointer pressure is 0.5 while a button is held. In human mode the first pointer position is random within 15–85% of the viewport. With `pointerGrid`, pointer coordinates lie on the device pixel grid and no move is sent without motion. Tab input calls `Page.bringToFront` only when another tab may be in front      |
| Browser mechanisms     | The sandbox, site isolation and CSP stay on. Pipe does not listen on a debugging TCP port; WebSocket still supports local and remote connections. Every launch skips first-run UI; the agent preset also disables the search engine choice screen, the crash-restore bubble and background throttling, and sets `--password-store=basic`: on Linux, Chrome then encrypts saved passwords and cookies with its built-in key instead of the system keyring, so it never prompts for the keyring, and a persistent profile whose data was encrypted through the keyring cannot read that data |

When no context is specified, Chromium wraps a DOM node in the main world of the frame it belongs to; see the [ResolveNode source](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/inspector/resolve_node.cc). [V8's objectId format](https://github.com/v8/v8/blob/main/src/inspector/remote-object-id.cc) is an internal V8 implementation detail and can change between versions.

The independent [Chromium preview workflow](../.github/workflows/chromium-preview.yml) runs Beta, Dev and Canary on Linux with Node.js 24: weekly, on manual dispatch and on PRs that change relevant core or benchmark files. It records the actual browser version and runs `test:audit`, `test:compat` (main-world discovery, navigation, OOPIF and context invalidation over Pipe and WebSocket), the [native launch environment](native-environment.md) and site-data clearing tests, the browser comparison checks and the [Worker startup environment benchmark](worker-environment.md), without retries. Its results do not gate releases, which wait only for the regression and platform workflows on the tagged commit. An incompatible discovery format raises `UnsupportedError`; the library leaves the Runtime domain disabled.

Reading the full AX tree costs time on large pages (see [performance phases](performance-phases.md)), and alternating text edits with full AX reads makes Chrome retain some Blink memory until navigation (see the [soak test](soak.md)). The page-owned probes record DOM and event changes; AX reads also affect timing and memory use. The [browser comparison benchmark](differential-audit.md) separates launch flags, endpoint, raw connection, library initialization, overrides and operations.

## Tests

```sh
npm run test:audit
npm run test:all
```

- `test/integration/runtime.test.ts` captures the real messages passed to `Transport.send` from before the browser starts. It covers both transports, four kinds of frame (including nested OOPIFs), Chinese text input, closed shadow roots, JSHandle, navigation, BFCache, popups and WebSocket reconnection, and asserts zero disabled domains, bindings and automatic init-script commands. A separate browser enables Runtime explicitly to test collection of those commands and the executionContextCreated/consoleAPICalled events.
- The input, environment, diagnostics, signal, churn and presentation integration tests, the HTTP/socket/embedded MCP tests and the soak test also assert that no disabled command is sent automatically.
- A page-owned probe compares main-world globals, element properties, DOM structure and attribute mutations, console functions and the webdriver getter before and after each operation. Queries and input leave none of these traces; in all four kinds of frame, webdriver is false and the getter is native. The page can still observe mouse events, form values and scrolling.
- In Chrome 156, the Error.stack getter is not read even in the configuration with Runtime enabled, and Error.name is read by the console call itself. The tests therefore assert on protocol commands and events; the Error.stack probe does not distinguish the two configurations.
- `test/integration/stealth.test.ts` pins the UA/UA-CH, pointer pressure and key sequences. Unit tests cover incompatible objectIds, wrong worlds or documents, cleanup of temporary handles, navigation during discovery, and recovery after a context disappears.

## Third-party detectors

Tested with Chrome 156 on GitHub-hosted Windows and Ubuntu runners, without DevTools open. Each run used a new temporary profile. Headful runs on Linux used `virtualDisplay`.

### Open-source detectors

Both detectors are served unchanged from their pinned commits by a local server. Each runs in all four combinations of headful/headless × Pipe/WebSocket, without changing the UA, fonts, timezone or network egress:

- [rebrowser-bot-detector e1a25b1](https://github.com/rebrowser/rebrowser-bot-detector/tree/e1a25b1ff264cc9a5b5ea7fe8a6dfc26e3b1c718): no positive hits on either system. After the calls its README asks for (a main-world `dummyFn()` call, the sourceURL probe and an isolated-world query), `dummyFn`, `sourceUrlLeak`, `navigatorWebdriver`, `viewport`, `useragent`, `bypassCsp`, `pwInitScripts` and `runtimeEnableLeak` pass, and `mainWorldExecution` does not see the isolated-world query. The exposeFunction check does not apply, and runtimeEnableLeak relies on the stack probe described above.
- [Brotector 98b3309](https://github.com/ttlns/brotector/tree/98b330999e9928a226ca0c8254dddf909d1583bd): each combination clicks the page's button with the instant and the human (seed=42) policy with the crash probe off, and with the instant policy with it on. No detection callback fires, and nothing crashes with the crash probe on.

### Online detection pages

CreepJS, BrowserScan and Pixelscan over Pipe. The runners' egress is a Microsoft datacenter address in the US. There was no request interception and no proxy or WebRTC restriction, and only the columns named below change the UA or the environment. The headless column uses the native HeadlessChrome UA (the default). Once the verdict settled, each cell moved the pointer twice and scrolled down and up; no verdict changed afterwards.

- BrowserScan's Robot verdict in headless mode comes from its User-Agent check. With `maskHeadless`, its Webdriver, User-Agent, CDP and Navigator checks all pass, while CreepJS still scores 33% headless: the mask changes only the UA and UA-CH.
- Pixelscan reported Timezone spoofed and Proxy detected, because the runners use UTC while the site places their datacenter address in America/Los_Angeles. On Linux, a headful launch with [`nativeEnvironment`](native-environment.md) set to that timezone and `en-US` removed Timezone spoofed and kept the other verdicts of the headful, instant column.
- On Linux, Pixelscan also reported Masking detected in every cell, including those without any override; on Windows it reported No masking detected. The library does not change canvas, WebGL, audio or font output.
- These pages report the same labels with instant and human input. Their checks cover browser and environment fields rather than click or typing behavior.
- In every cell webdriver was false and no forbidden protocol command was sent. CreepJS percentages are scores assigned by that page's checks.

## Signals that remain observable

1. **Headless**: `maskHeadless` changes only the UA and UA-CH. Screen size (for example 800×600) and other browser settings stay unchanged. Headful is the default; without a graphical desktop, choose `headless: true` or use `virtualDisplay` on Linux.
2. **Execution world**: `tab.evaluate()` and `frame.evaluate()` run in the main world by default so that they can reach the page's own objects, which means the page can hook its own methods. Queries and `Element.evaluate()` default to an isolated world; for other generic DOM reads pass `{ world: 'isolated' }`. Isolated worlds share the DOM.
3. **Environment consistency**: the UA, Client Hints, language, timezone, screen, fonts, GPU, worker values and proxy egress each need to be measured. Headful and headless modes both keep native values by default; the optional mask changes only the page/Dedicated Worker UA and can disagree with Shared/Service Workers. The effect of `setEnvironment()` depends on the field and execution context; OS fonts and GPU hardware stay unchanged.
4. **Input**: clicks and text are dispatched through CDP Input, and the page can still observe timing and trajectories. DOM value changes such as select dispatch synthetic events. These events are generated by CDP or page scripts rather than operating-system input devices.
5. **External factors**: DevTools or other CDP clients that were already attached, domains the caller enables manually, TLS/IP reputation, and proxy and WebRTC egress are outside what the defaults cover. Pipe only reduces exposure of a local debugging port.
